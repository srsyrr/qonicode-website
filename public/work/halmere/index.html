Halmere

A fictional homeware brand on a new Shopify development store. One best-selling plate set gets a richer product page, built from new sections the owner can edit alone in the theme editor; every other product keeps Dawn's normal page. I wrote the spec and a greyscale wireframe first, then built against it.

Section by section

S-01 Feature highlights

7 criteria · 15 settings + 4 per feature

Brief

An image next to up to six short features (icon, title, text), so a shopper sees what makes the plates different. The owner changes every part without code.

Acceptance criteria

  • Image left or right on desktop, above or below on phones
  • Features in 1 or 2 columns from 990 px; 1 column on phones
  • Images download at a size close to how wide they show (smaller file at 390 than at 1440)
  • With no image, the features use the full width
  • The button shows only when it has both a label and a link
  • A 120-character heading or one very long word wraps with no overflow at 360 px
  • Up to 6 features: add, remove, reorder in the editor Passed in preview; editor check to do

Below the main product area: the plan on the left of the divider, the built section on the right.

Change log, how to edit and what else was tested

Change log

  • sections/feature-highlights.liquid (new)Schema, markup and CSS in one file; styles only apply inside this section
  • templates/product.hero.json (new)The hero page: Dawn's product area, then the new sections

How to edit

  1. Customize → page picker → Products → hero.
  2. Click Feature highlights: heading, image, image position, columns, button, colour scheme, padding.
  3. Add Feature for a new row (up to 6); drag to reorder; an empty feature is not shown.

Also tested

  • Every one of its settings changed one at a time, checked on the page, then restored
  • An image instead of an icon, no blocks at all, blocks reordered
  • Uses section blocks, not theme blocks, so it also fits older themes agencies maintain

S-02 Comparison table

4 criteria · up to 12 rows

Brief

A short “Halmere vs a typical plate” table. Each cell is a check, a cross or a few words, and screen readers hear real words instead of icons.

Acceptance criteria

  • A real table: caption from the heading, row and column headers
  • ✓ and ✗ are read out as the “Yes” and “No” labels
  • At 360 px the page never scrolls sideways; long text wraps inside its cell
  • A table with no filled rows shows nothing on the storefront, no empty heading or border

The highlighted column can be switched off in the editor.

Change log, how to edit and what else was tested

Change log

  • sections/comparison-table.liquid (new)Schema, table markup and CSS; ✓ / ✗ use Dawn's own icons
  • templates/product.hero.jsonFive sample rows from the spec

How to edit

  1. Click Comparison table: heading, intro, the three column headings, highlight on or off.
  2. Add Row: a feature name, then Check, Cross or Text for each side.
  3. Screen-reader text for ✓ and ✗ is a setting, so it can follow the store language.

Also tested

  • Highlight off, more rows, very long cell text at 360 px
  • Name only your own products: the “Other” column never names a brand

S-03 FAQ

4 criteria · up to 20 questions

Brief

Answers to common questions under the product, with a contact line. Keyboard users can open and close every answer.

Acceptance criteria

  • Answers open and close with mouse, Enter and Space; focus is visible
  • “Only one answer open at a time” closes the first answer when a second opens
  • Structured data on: one FAQ block in the page code matching the questions; off: none
  • No filled questions: nothing on the storefront, a dashed hint in the editor

Built on the browser's own open / close element, so it needs no JavaScript.

Change log, how to edit and what else was tested

Change log

  • sections/product-faq.liquid (new)Native <details> per question; Dawn's accordion styles
  • templates/product.hero.jsonFive sample questions

How to edit

  1. Click FAQ: heading, open the first answer, one answer at a time, text below the questions.
  2. Add Question: a question and an answer; one without the other is not shown.
  3. Turn on FAQ structured data for one FAQ per page only.

Also tested

  • Keyboard path with visible focus in Chromium and Edge
  • Open first answer on and off; one at a time on and off

S-04 Sticky add to cart (phones)

4 criteria · stretch goal

Brief

On phones, a bar with the product name, price and Add to cart appears once the main button scrolls away, so a shopper never has to scroll back up.

Acceptance criteria

  • Shows below 750 px only, after the main Add to cart scrolls out of view
  • Adds the chosen colour, set and quantity, using Dawn's own product form
  • Updates when the variant changes; no layout shift
  • Not there on desktop, or when JavaScript is off

Phone, scrolled past the main button: Dawn's default page (left) and the hero page with the bar (right).

Change log, how to edit and what else was tested

Change log

  • sections/sticky-add-to-cart.liquid (new)The bar, its screen-reader name and colour scheme
  • assets/sticky-add-to-cart.js (new)Shows the bar when the main button leaves the screen; its button clicks Dawn's button
  • sections/main-product.liquidThe only change to a Dawn file: a 3-line guard that hides an empty Material or Care tab

How to edit

  1. Click Sticky add to cart: the bar name for screen readers and the colour scheme.
  2. Material and Care tabs: Products → the product → Metafields. An empty field hides its tab.
  3. Use the page for another product: in the product admin, Theme template → hero.

Also tested

  • Products on the default template are pixel-identical to untouched Dawn (3 products × 2 widths)
  • Theme Check: the same 9 warnings as untouched Dawn, 0 errors

The plan is a greyscale wireframe drawn for this exercise, not a client design. Product photos are stock stand-ins.

Not tested yet

Firefox, Safari and a real phone, and adding the sections by hand in the Shopify theme editor (they are on the owner's checklist). Right-to-left languages.
